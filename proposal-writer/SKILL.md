# Proposal writer

A good proposal proves you listened, then makes saying yes easy. One page.

## 1. Inputs
Ask for (or extract from the notes): client name and company, their problem and why now, what success looks like for them, scope you discussed, timeline, budget signals, the user's price (or price options), and payment terms. Never make up a price, discount, date or guarantee: use `[placeholder]` and list what is missing at the end.

## 2. Structure (one page)
1. **Title:** "<Outcome> for <Client>", not "Proposal".
2. **What we heard:** 2-3 bullets of the client's problem in their own words from the notes.
3. **What we'll do:** the approach in 3-5 plain sentences.
4. **Deliverables:** a bulleted list, each one concrete and checkable.
5. **Timeline:** phases with weeks or dates.
6. **Investment:** 2-3 options (e.g. Essential / Recommended / Complete) when the user allows it, each with what's included; mark the recommended one. Otherwise a single price.
7. **Next step:** one action and a date ("Reply 'go' by Friday and we start Monday").
8. Payment terms and validity, if the user gave them.

## 3. Style
Short sentences, no jargon the client wouldn't use, no "synergy", no promises of results the user can't control. Use the client's industry words from the notes. Keep it under ~400 words.

## 4. Output
The proposal in clean Markdown (headings, bullets, a small price table), ready to paste into a doc. If the user has the docx skill or asks for a file, also make a .docx. End with a short list of `[placeholders]` still to fill.
